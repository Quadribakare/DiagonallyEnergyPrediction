## Running the project A to Z

### Step 1 — Clone and install dependencies

```bash
git clone <repo-url>
cd diagonally-energy-prediction
pip install -r requirements.txt
```

### Step 2 — Set up environment variables

```bash
copy .env.example .env
```

Open `.env` and fill in every value:

```
MODEL_PATH_FORECAST=src/model/trained/model_forecast.joblib
API_HOST=0.0.0.0
API_PORT=8000
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_ANON_KEY=your_supabase_anon_key
SUPABASE_SERVICE_ROLE_KEY=your_supabase_service_role_key
ELECTRICITY_TARIFF_GBP_PER_KWH=0.34
ANTHROPIC_API_KEY=your_anthropic_api_key
```

See `docs/env.md` for what each variable does and where to get the values.

### Step 3 — Add the raw dataset

Place `House_1.csv` (REFIT Smart Home Dataset, House 1) at:

```
data/raw/House_1.csv
```

This file is gitignored and must be sourced separately from the REFIT dataset.
Expected columns: `Unix, Aggregate, Appliance1 … Appliance9`
Expected date range: October 9 2013 – July 10 2015

### Step 4 — Run the training pipeline

This preprocesses the raw CSV, trains the RandomForest, evaluates it on 9 held-out test days,
and writes three files to `src/model/trained/`:

```bash
python scripts/run_training_forecast.py
```

After this completes you will have:
- `src/model/trained/model_forecast.joblib` — trained model
- `src/model/trained/model_evaluation.json` — MAE/RMSE/MAPE metrics
- `src/model/trained/demo_day.json` — held-out demo day (2015-02-10)
- `data/processed/train.csv` and `data/processed/test.csv`

Do not retrain by calling anything inside the API — always use this script.

### Step 5 — Run the tests

```bash
pytest
```

All tests must pass before starting the API. The test suite uses a mock Supabase client
so no live DB connection is needed.

### Step 6 — Start the API server

```bash
uvicorn src.api.main:app --host 0.0.0.0 --port 8000 --reload
```

The server is ready when you see:
```
INFO:     Application startup complete.
```

The `--reload` flag restarts the server on file changes (development only — omit in production).

### Step 7 — Open the frontend

Navigate to:

```
http://localhost:8000/frontend/forecast.html
```

The forecast form pre-fills with the demo day values (2015-02-10). Click **Predict** to get
a single-day prediction showing Wh, kWh, estimated cost in GBP, and temperature.

### Step 8 — (Optional) Seed Supabase with test data

If you want to populate the `forecast_requests` table with the 9 test-split days:

```bash
python scripts/seed_supabase.py
```

Requires a live Supabase connection (`SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` set in `.env`).

## API endpoints at a glance

| Method | Route | What it does |
|---|---|---|
| GET | `/health` | Liveness check — returns `{"status": "ok"}` |
| GET | `/api/v1/models/evaluation` | MAE/RMSE/MAPE + per-day breakdown for 9 test days |
| POST | `/api/v1/forecast/predict` | Single-day prediction from 7–9 user inputs |
| GET | `/api/v1/forecast/7d` | 7-day rolling forecast + weekly bill projection |

Full request/response shapes are in `docs/api-contracts.md`.

## Common problems

| Problem | Fix |
|---|---|
| `model_forecast.joblib not found` | Run `scripts/run_training_forecast.py` first |
| `model_evaluation.json not found` | Run `scripts/run_training_forecast.py` first |
| `House_1.csv not found` | Place the REFIT House 1 CSV at `data/raw/House_1.csv` |
| Temperature fetch fails | Supply `temp_mean_c` and `temp_min_c` directly in the POST body |
| Supabase insert fails | Check `SUPABASE_SERVICE_ROLE_KEY` is set — not the anon key |
| Tests fail on import | Check `.env` is present and all required variables are set |
